<gotchas>
1. **`currentUser.id` NU este `auth.uid()`.** In `hooks/useDataProvider.ts` (linia ~300) `setCurrentUser` face spread peste `activeCtx.sportiv`, deci `currentUser.id` e id-ul randului din `sportivi` cand userul are profil de sportiv. De aceea `procesat_de` NU se scrie din client, ci printr-un trigger `BEFORE UPDATE` care foloseste `auth.uid()`.
2. **Politicile RLS permisive se combina cu OR.** O politica `Admin_Club_Select` care verifica doar clubul activ, fara verificare de rol, ar da acces si INSTRUCTORULUI din acelasi club — incalcand D-12. Predicatul admin TREBUIE sa contina si verificarea de rol prin `public.utilizator_roluri_multicont`.
3. **`sportivi.user_id` poate fi nepopulat** pentru o parte din randuri. Legatura user↔sportiv trebuie verificata pe ambele cai (`sportivi.user_id` SAU `utilizator_roluri_multicont.sportiv_id`), altfel sportivii reali raman fara acces la propriile cereri.
</gotchas>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client browser → PostgREST/Supabase | Orice utilizator autentificat poate trimite `sportiv_id` arbitrar in payload-ul de INSERT pe `cereri_gdpr` |
| ADMIN_CLUB club A → randuri club B | Contextul de club activ vine dintr-un header injectat de client (`active-role-context-id`), deci nu e de incredere fara verificare server-side |
| trigger BEFORE UPDATE → auth.uid() | Singura sursa de adevar pentru identitatea celui care proceseaza cererea |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-01 | Elevation of Privilege | INSERT pe `cereri_gdpr` cu `sportiv_id` al altui sportiv | mitigate | Politica `Sportiv_Insert_Propriile_Cereri_GDPR` re-deriva legatura server-side prin `public.este_sportivul_meu(sportiv_id)`; `sportiv_id` din client nu e niciodata singura verificare (D-09) |
| T-28-02 | Information Disclosure | SELECT cross-club pe `cereri_gdpr` de catre ADMIN_CLUB din alt club | mitigate | `cerere_gdpr_sportiv_club_id(sportiv_id) = get_active_club_id()` prin join SECURITY DEFINER (precedent Faza 16), nu filtrare frontend |

| T-28-04 | Repudiation | Admin aproba o cerere, dar `procesat_de` e fals/gol (client trimite id gresit) | mitigate | Trigger `tr_cereri_gdpr_procesare` seteaza `procesat_de = auth.uid()` si `procesat_la = now()` server-side; clientul nu scrie aceste campuri |
