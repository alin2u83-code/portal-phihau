# Quick Task 260710-07l: Audit log nume utilizator + filtru + sesiuni/trafic - Context

**Gathered:** 2026-07-09
**Status:** Ready for planning

<domain>
## Task Boundary

Super Admin sa vada in Jurnal Audit (`components/JurnalAudit.tsx`) numele utilizatorului in loc de UUID brut, cu filtru pe nume (SearchableSelect: scriere + dropdown). Adaugat: vizualizare sesiuni de login (cine s-a logat, cat a stat activ) si trafic per profil — derivate din `audit_log` existent (evenimente LOGIN/LOGOUT), fara tabel nou.

</domain>

<decisions>
## Implementation Decisions

### Scope audit
- Filtrul de nume se aplica pe tot jurnalul audit existent (toate operatiile: INSERT/UPDATE/DELETE/SELECT_SENSIBIL/LOGIN/LOGOUT/ROL_SCHIMBAT), nu doar login/logout.

### Sursa date sesiuni/trafic
- Nicio schimbare de schema DB. Sesiunile se deduc din perechi LOGIN→LOGOUT existente in `audit_log` (tabel='auth', operatie='LOGIN'/'LOGOUT', user_id).
- Durata sesiune = timestamp LOGOUT - timestamp LOGIN pentru acelasi user_id, in ordine cronologica (following-logout dupa un login, fara alt login intre ele). Daca nu exista LOGOUT dupa un LOGIN (sesiune neinchisa / tab inchis fara logout), afiseaza ca "in curs" sau "necunoscuta" — nu inventa o durata.
- Precizie aproximativa acceptata (nu heartbeat/real-time online tracking).

### Tip filtru nume
- Foloseste componenta `SearchableSelect` deja existenta in `components/ui.tsx` (pattern folosit deja in Prezenta, Plati, Competitii, Sportivi, GestiuneExamene).
- Sursa nume: tabelul `utilizator_roluri_multicont` are `user_id` + `nume_utilizator_cache` (vezi `hooks/useUserRoles.ts`) — foloseste-l pentru a mapa user_id -> nume afisat in jurnal si in optiunile filtrului. Un user poate avea mai multe randuri (roluri multiple) — dedupe dupa user_id, ia primul nume_utilizator_cache non-null.

### Claude's Discretion
- Unde exact sa apara noua sectiune "Sesiuni / Trafic per profil": tab nou in JurnalAudit sau view separat legat din acelasi meniu (Super Admin) — decide functie de cel mai simplu pattern existent in app (vezi istoric-activitate / 260704-x9p ca precedent).
- Denumire coloane, iconite, format afisare durata (ex: "2h 15m").

</decisions>
