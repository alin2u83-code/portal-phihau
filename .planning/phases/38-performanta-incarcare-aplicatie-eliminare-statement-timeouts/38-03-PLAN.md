<objective>
Make the data hooks safe to start late and cheap to run: enabled guards on useSportivi/usePlati, count:'exact' only with pagination, chunked + paged attendance rows, and remove the three hidden second instances of the whole data provider.

Purpose: research cause #1 (request storm) and #5 (unbounded .in()). AdminDashboard, MartialAttendance and SportivDashboard call useDataProvider() directly (found during planning), which mounts a second full provider (roles, sportivi, plati, attendance, all critical/deferred queries, auth listener) every time those screens open - the SPORTIV dashboard and the federation admin dashboard double the startup load. This plan keeps every hook's API compatible; 38-04 does the wiring in useDataProvider.
Output: four hook/component groups changed, no new files.
</objective>
