Obiect 1 — `CREATE OR REPLACE FUNCTION public.an_fiscal_federatie(p_data date) RETURNS integer LANGUAGE sql IMMUTABLE` (D-01): returneaza `EXTRACT(YEAR FROM p_data)::int` cand `EXTRACT(MONTH FROM p_data) >= 9`, altfel `EXTRACT(YEAR FROM p_data)::int - 1`. Argumentul este obligatoriu (fara DEFAULT `CURRENT_DATE`), ca functia sa ramana IMMUTABLE si sa poata fi testata determinist cu date fixe.

Obiect 2 — `CREATE OR REPLACE FUNCTION public.activeaza_taxa_anuala(p_sportiv_id uuid) RETURNS void LANGUAGE plpgsql SECURITY DEFINER SET search_path = public, pg_temp`. `SET search_path` este obligatoriu pe orice functie SECURITY DEFINER, altfel apelantul poate deturna rezolvarea numelor de tabele.

Corpul implementeaza exact pasii din D-07, in ordinea din spec:
1. Iesire imediata (`RETURN`) daca `p_sportiv_id IS NULL`.
2. `v_an_fiscal := public.an_fiscal_federatie(CURRENT_DATE)`.
3. Gate de idempotenta: `INSERT INTO public.vize_sportivi (sportiv_id, an, status_viza, data_platii) VALUES (p_sportiv_id, v_an_fiscal, <valoarea din verdictul B3>, CURRENT_DATE) ON CONFLICT (sportiv_id, an) DO NOTHING RETURNING id INTO v_viza_id`. Foloseste ca `status_viza` valoarea reala acceptata de CHECK-ul live consemnata in B3 (migratia din repo declara `'Activ'`; spec-ul scrie `'Activa'` si este gresit). `data_platii` se completeaza aici pentru ca este NOT NULL (B4) — reprezinta data activarii vizei, nu data incasarii.
4. `IF v_viza_id IS NULL THEN RETURN; END IF;` — sportivul are deja viza pe sezon, nimic de facut.
5. `SELECT club_id INTO v_club_id FROM public.sportivi WHERE id = p_sportiv_id`. Daca `v_club_id IS NULL`, `RAISE EXCEPTION` cu mesaj romanesc care numeste sportivul: sportivul nu are club asociat, taxa federala nu poate fi atribuita niciunui decont; sportivul trebuie repartizat la un club inainte de inscriere. Motivatia (discretie de implementare, in spiritul D-08): un sportiv fara `club_id` — situatie reala aparuta la import, vezi memoria proiectului — ar participa la activitati fara sa fie niciodata facturat, invizibil pentru federatie. Esecul zgomotos este preferabil scurgerii tacute.
6. `SELECT suma INTO v_suma FROM public.taxa_anuala_config WHERE an_fiscal = v_an_fiscal`. Daca `v_suma IS NULL`, `RAISE EXCEPTION` (D-08) cu mesaj care contine sezonul formatat `v_an_fiscal || '-' || (v_an_fiscal + 1)` si instructiunea concreta: SUPER_ADMIN_FEDERATIE trebuie sa seteze suma in Taxe Anuale, tabul Taxa Federatie (FRQKD). Nu prinde exceptia — rollback-ul complet al tranzactiei sursa este comportamentul cerut.
7. `INSERT INTO public.plati (sportiv_id, club_id, suma, descriere, data, tip, status, an)` cu `tip = 'FRQKD'`, `status = 'Neachitat'`, `descriere = 'FRQKD Sezonul ' || v_an_fiscal || '-' || (v_an_fiscal + 1)` (formatul identic cu cele 37 de randuri istorice), `data = CURRENT_DATE`, `an = v_an_fiscal`, `RETURNING id INTO v_plata_id`. Nu completa `observatii` — coloana este NOT NULL in unele scheme; daca verdictul din audit (interogarea 1) arata `is_nullable = 'NO'` pe `plati.observatii`, trimite sirul gol.
8. `UPDATE public.vize_sportivi SET plata_id = v_plata_id, data_platii = CURRENT_DATE WHERE id = v_viza_id`.
9. `INSERT INTO public.deconturi_federatie (club_id, an_fiscal, tip_activitate, suma_totala, nr_participanti, status_plata, data_generare) VALUES (v_club_id, v_an_fiscal, 'FRQKD', 0, 0, 'In asteptare', now()) ON CONFLICT (club_id, an_fiscal) DO NOTHING` — get-or-create, sigur la inserari concurente.
10. `UPDATE public.deconturi_federatie SET suma_totala = coalesce(suma_totala, 0) + v_suma, nr_participanti = coalesce(nr_participanti, 0) + 1 WHERE club_id = v_club_id AND an_fiscal = v_an_fiscal RETURNING id INTO v_decont_id` — incrementul se face pe UPDATE, nu pe recalculare prin agregare, pentru ca UPDATE-ul ia lock pe rand si serializeaza corect doi sportivi inserati simultan.
11. `INSERT INTO public.decont_sportivi (decont_id, sportiv_id, an) VALUES (v_decont_id, p_sportiv_id, v_an_fiscal) ON CONFLICT DO NOTHING`.

Obiect 3 — `CREATE OR REPLACE FUNCTION public.trg_activeaza_taxa_anuala() RETURNS trigger LANGUAGE plpgsql SECURITY DEFINER SET search_path = public, pg_temp`: citeste numele coloanei cu ID-ul sportivului din `TG_ARGV[0]`, extrage valoarea prin `(to_jsonb(NEW) ->> TG_ARGV[0])::uuid`, apeleaza `public.activeaza_taxa_anuala(...)` si returneaza `NEW`. O singura functie generica acopera si `sportiv_id` si `practicant_id`, fara patru copii aproape identice.

Obiect 4 — cele patru triggere (D-06), fiecare precedat de `DROP TRIGGER IF EXISTS` pe tabela corespunzatoare, toate `AFTER INSERT ... FOR EACH ROW EXECUTE FUNCTION public.trg_activeaza_taxa_anuala(<coloana>)`:
