## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pg_cron (postgres) → Edge Function (HTTP) | Apel autentificat cu cheie `service_role`; cheia nu are voie sa ajunga in git |
| Edge Function → gateway SMS al fiecarui club (HTTPS extern) | Iesire catre internet; gateway-urile sunt tunele ngrok/CF controlate de cluburi |
| `sms_queue` → telefon sportiv (posibil minor) | Prima iesire reala catre persoane fizice din toata faza 30 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-06-01 | Information Disclosure | Cheia `service_role` scrisa literal intr-o migratie comisa in git | mitigate | Interdictie explicita in actiune; cheia se ia doar din `current_setting('app.service_role_key')` sau din `vault.decrypted_secrets`; verificare automata prin grep dupa pattern de JWT in fisierul de migratie |
| T-30-06-02 | Denial of Service (cost + reputatie) | Golirea brusca a unui backlog istoric → avalansa de SMS retroactive catre sportivi | mitigate | `UPDATE ... SET status='cancelled'` pe tot backlog-ul, executat INAINTE de `cron.schedule` in acelasi fisier; verificat prin `backlog_vechi = 0` |
| T-30-06-03 | Elevation of Privilege | Cine poate declansa procesarea cozii | accept | Edge Function-ul nu primeste parametri si nu accepta selectie de destinatar; ruleaza cu `SUPABASE_SERVICE_ROLE_KEY` din mediul propriu, neschimbat de acest plan |
| T-30-06-04 | Denial of Service (cost) | Bucla de retry pe mesaje care esueaza permanent (cluburi fara gateway) | accept | Edge Function-ul respecta deja `retry_count < max_retries` si marcheaza `failed` definitiv; cluburile fara gateway sunt identificate si listate in Task 1 |
