# Phase 26 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn/MUI explicitly forbidden by project `CLAUDE.md` ("`components/ui.tsx` = design system intern — nu se importă Shadcn/MUI") |
| Preset | not applicable |
| Component library | custom internal (`components/ui.tsx`) — reuse `Modal`, `Input`, `Button`, `FormSection`, `Card`, `CredentialeContModal` verbatim, zero new primitives needed |
| Icon library | `lucide-react`, re-exported via `components/icons.tsx` — this phase uses `BuildingOfficeIcon` (club section) and `UserPlusIcon` (admin section), both already exported |
| Font | `Inter` (sans, all UI text) / `JetBrains Mono` (mono, credential values — CIF, email, parolă) — declared in `tailwind.config.js` |

This phase does **not** introduce a new screen or new design-system component. It extends the existing `ClubFormModal` (`components/CluburiManagement.tsx`) with a conditional admin sub-section, and reuses the existing `CredentialeContModal` (`components/ui.tsx`, already used by `CreateAccountModal.tsx`) unmodified as the post-creation result screen. All colors, spacing and type styles below describe how the *existing* tokens are applied to the *new* fields — they are not new tokens.

## Implementation Notes (form structure)

Two-section form inside the existing `Modal` (`max-w-lg sm:max-w-2xl`, no new modal size needed):

1. **Secțiune "Date Club"** (icon `BuildingOfficeIcon`) — unchanged from today:
   - `Nume Club` — full width, required
   - `CIF / CUI (Opțional)` + `Oraș (Opțional)` — 2-col grid (`grid-cols-1 sm:grid-cols-2 gap-4`), unchanged

2. **Secțiune "Date Prim Administrator"** (icon `UserPlusIcon`) — **new**, rendered **only when `!clubToEdit`** (create mode; per D-01 never shown on edit):
   - `Nume Admin` + `Prenume Admin` — 2-col grid, both required
   - `Email Admin` — full width, required, `type="email"`, placeholder `email@exemplu.ro` (no pre-filled synthetic domain — this is a real login credential, unlike the `@frqkd.ro` magic-link pattern)
   - **No username field** — derive silently as `email.split('@')[0]` (same default already used in `hooks/useRoleAssignment.ts`), consistent with keeping the form minimal
   - **No password field** — password is generated automatically server/client-side (D-05), never typed by SUPER_ADMIN
   - Helper text directly under the section heading, `Body` style, `var(--t-text-muted)`: *"Parola va fi generată automat și afișată după creare — o veți transmite manual noului admin."*

3. **Footer** — unchanged button row (`Anulează` secondary + submit primary), submit label changes by mode (see Copywriting Contract).

4. **Retry/error sub-state (D-07)** — if club insert succeeds but admin creation fails, the modal does **not** close and does **not** just toast — it swaps the form body for an inline error banner (see Copywriting Contract → Error state) with a dedicated retry button. The already-created club is not re-inserted on retry.

5. **Result screen** — on full success, close `ClubFormModal` and open the existing `CredentialeContModal` unmodified, passing `numeSportiv` as `"{prenume} {nume} — Admin {numeClub}"` so the generic "Credențiale pentru …" subtitle reads correctly for a club admin instead of a sportiv.

## Spacing Scale

Declared values (must be multiples of 4) — identical to the scale already in use across `ui.tsx` (Tailwind default spacing, no custom scale file):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (`gap-1`, `mr-1`) |
| sm | 8px | Compact inline spacing (`gap-2`, `px-2 py-1` chips) |
| md | 16px | Default form field spacing (`space-y-4`, `gap-4` grids) — used between the two new admin inputs and between sections |
| lg | 24px | Section padding (`p-6` modal body on `sm:` breakpoint) |
| xl | 32px | Not used in this phase (no full-page layout) |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions: none. Buttons keep the existing 44px+ touch target via `size="md"` (`px-6 py-3`) — no icon-only controls introduced by this phase.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label | 12px (`text-xs`, uppercase, tracking-wide) | 700 (bold) | 1.4 |
| Heading | 16px mobile / 18px desktop (`text-base sm:text-lg`) | 700 (bold) | 1.2 |
| Display | not applicable — this phase is confined to modal content; the modal title (Heading, 18px) is the largest text introduced |

Existing reused components (`Button` uses `font-medium`/500, `EmptyState` title uses `font-semibold`/600) keep their own pre-existing styling unchanged — this contract governs only the new content authored for this phase (section sub-headers "Date Club" / "Date Prim Administrator", the admin-field labels, and the helper/error copy), which sticks to exactly 2 weights: 400 and 700.

## Color

This project uses a CSS-variable theming system (`index.css`, `--t-*` tokens, dark-mode default, 20 selectable themes) rather than fixed hex — so the contract is expressed in token roles, which resolve correctly under every installed theme.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--t-bg)` (default theme: `#020617`) | Modal backdrop / app background behind the dialog |
| Secondary (30%) | `var(--t-surface)` / `var(--t-surface-2)` (default: `#0f172a` / `#1e293b`) | Modal body surface, header/footer bars, input backgrounds (`var(--t-input-bg)`) |
| Accent (10%) | `var(--t-primary)` (default: `#3b82f6`, blue) | Reserved for: primary submit button ("Creează Club și Admin" / "Salvează"), input focus ring, the section icons (`BuildingOfficeIcon`, `UserPlusIcon`) |
| Destructive | `var(--t-status-danger)` | Reserved for: inline field validation errors, the D-07 "admin creation failed — retry" banner. **Not** used for delete (this phase adds no delete action) |

Additional semantic colors reused as-is from the existing `CredentialeContModal` pattern (not new, listed for completeness):
- `var(--t-status-success)` (green) — reserved for the "Cont creat cu succes" confirmation banner only.
- `var(--t-status-warning)` (amber) — reserved for the "transmite parola manual sportivului/adminului" caution note only.

Accent reserved for: primary CTA button, input focus rings, the two new section icons. Never used decoratively elsewhere in this form.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (create mode, new club) | **"Creează Club și Admin"** — distinct from the unchanged edit-mode label below, since this action now performs two writes |
| Primary CTA (edit mode, existing club) | **"Salvează"** — unchanged, admin fields are not shown so the label stays generic |
| Retry CTA (D-07 partial failure) | **"Reîncearcă Crearea Contului Admin"** — club is not re-created; only the admin-account step is retried |
| Admin section helper copy | *"Parola va fi generată automat și afișată după creare — o veți transmite manual noului admin."* |
| Empty state heading | *(reuse existing `Card` empty state in `CluburiManagement`, no separate heading element)* |
| Empty state body | *"Nu există cluburi înregistrate. Adăugați primul club — formularul creează automat și primul admin al clubului. Folosiți butonul de mai sus."* (updates today's generic copy to reflect the new combined flow) |
| Error state (club insert fails) | Unchanged — existing `showError()` toast copy in `CluburiManagement.tsx` (CIF duplicat / RLS / generic), no changes needed |
| Error state (admin creation fails after club created — D-07) | Inline banner inside the modal, `var(--t-status-danger)` tinted, `AlertCircleIcon`: *"Clubul '{nume}' a fost creat, dar contul de admin nu a putut fi creat: {mesaj eroare}. Clubul nu se creează din nou — apăsați mai jos pentru a reîncerca doar crearea contului de admin."* + button "Reîncearcă Crearea Contului Admin" |
| Result screen title | Unchanged (`CredentialeContModal`): *"Cont creat cu succes"* |
| Result screen subtitle | *"Credențiale pentru {prenume} {nume} — Admin {numeClub}"* (new composite value passed into the existing `numeSportiv` prop) |
| Result screen caution note | Unchanged (`CredentialeContModal`): *"Transmite aceste credențiale sportivului. Parola va fi cerută a fi schimbată la prima autentificare."* — reads correctly as-is for an admin account too (same `trebuie_schimbata_parola` mechanism) |
| Destructive confirmation | Not applicable — no destructive action is introduced by this phase. The existing "Șterge Club" flow (`ConfirmDeleteModal`) is untouched and out of scope. |
